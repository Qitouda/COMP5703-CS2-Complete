## 三份关键材料

- [报告字段合同 v0.1](../01_统一规范/可信度核查报告字段合同_v0.1.md)：前后端与数据组共同使用的请求、状态、结果、证据和异常约定，含合成响应示例。

- [技术难点与提前验证](../03_过程与交付/接口、模型与联调记录/第二轮_可信度核查技术难点与提前验证.md)：说明解析、证据、引用匹配、仓库关联和外部故障应先验证什么；不另列分工。

两份新规范都是评审草稿，尚未批准或完成样本校准；可做明确标注的试验。合成例、文档交付不代表真实接口、模型效果或验收已完成。

## 各组怎么读

全员先读产品基线，再看[团队总览](../02_各组任务/第二轮_团队总览.md)和[任务主表](../03_过程与交付/第二轮_交付任务清单.md)。

| 小组 | 后续顺序 |
|---|---|
| 产品 | Rubric 的汇总及边界案例 → 合同的总评与异常 → 验收路径 |
| 数据 | Rubric → 合同的证据和三类检查 → 样本与复评记录 |
| 后端 | 新合同 → Rubric 与边界案例 → 技术难点 → 本组任务单 |
| 前端 | 新合同的输入、状态、总评和示例 → Rubric 边界案例 → 本组任务单与验收路径 |

执行人、日期、状态和交付证据只在任务主表维护。各组任务单解释交付要求；真实样本填写[复评记录](../03_过程与交付/数据样本与%20Rubric/第二轮_可信度核查样本与复评记录.md)，流程验证填写[验收路径](../03_过程与交付/验收与演示材料/第二轮_整体验收路径.md)。

`99_历史归档` 不用先读，追溯时再查；[旧评分合同](../01_统一规范/旧五维评分字段合同_v0.4.md)仅供旧功能维护与回归。课程材料不属于本页开发阅读范围。
