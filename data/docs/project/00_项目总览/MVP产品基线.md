## 1. 要解决的问题

主要用户是正在构思研究、寻找相关 ML 文献的读者。论文很长，标题、摘要和引言可能给人很强的印象，但关键主张、结果、引用或可复现材料未必经得起核查。用户希望在投入精读和引用前，快速知道哪些地方值得怀疑，并直接看到依据。

一句话定位：**对机器学习论文进行有来源、可回查的可信度核查，提示阅读和引用前需要注意的风险。** 系统不是学术不端调查机构，不判断作者是否有意欺骗，也不保证未发现问题的论文一定可靠。论文发表在某会议或期刊，不自动构成可信度证明或风险证据。

本轮关注的“问题论文”是主张或材料**靠不住、存在可核查漏洞**的论文，而不是语言不流畅、创新有限、没有达到 SOTA 或与用户课题不相关的论文。后几类可以影响阅读价值，但不能直接等同于可信度风险。

## 2. 用户与范围

- 产品面向**所有 ML 研究论文**，不按 ICLR 或其他 venue 限制，也不以接收、发表状态作为准入条件。会议论文、期刊论文、预印本和未发表稿件均可作为输入；实际可分析程度由解析质量和内容决定。
- 沿用现有 arXiv 链接／ID 与 PDF 上传入口。本轮优先核对已有英文 ML 处理能力；非英文稿件属于产品目标，但在完成解析和评测前不能宣称已可靠支持。
- 非 ML 内容、无法可靠解析的文档以及服务失败应给出明确原因，不生成伪造的可信度结论。
- 原型在本地运行，可以联网调用公开文献元数据、论文附属材料及公开仓库／issue 等工具或 API。不安排公网部署、账号、付费与复杂数据保留策略。
- “帮助审稿人”不写入本轮目标、用户场景或验收项。

## 3. 两个并列功能

| 功能 | 当前处理 | 回答的问题 |
|---|---|---|
| 现有论文评分 | 保持原有五维报告、输入和证据功能，并做必要回归；历史的 ICLR-inspired 文案仅描述旧评分规则，不能作为整个产品的范围 | 论文的研究价值、表达和论文内论证如何？ |
| 新增 **Paper Credibility Check** | 独立入口与报告；不自动重跑、展示或混算旧五维评分 | 哪些主张、引用或复现相关材料存在需要核查的风险？ |

两个功能可复用论文解析、任务状态和证据定位等基础能力，但**评分体系、总分和结论必须区分**。第一版不制作跨两个功能的联合分数，也不以旧五维低分判定论文可疑。用户可分别查询并自行决定是否继续阅读或引用。

## 4. 新功能的首批检查维度

下列三个维度覆盖目前确认的 client 示例；维度名称是产品工作名，精确判准由数据组形成样本和 Rubric 后确定。

### 4.1 Claim–Evidence Consistency（主张与证据一致性）

从摘要／引言提取影响读者判断的核心、可核查主张，寻找方法、实验、结果、表格、附录或结论中的对应依据。报告区分：找到支持、仅有部分支持、后文未找到对应结果、发现具体冲突、无法判断。不得把一般性的研究动机或修辞自动当成可验证结果。哪些主张必须纳入、怎样处理理论／综述／数据集等不同论文，由数据组研究并人工验证。

### 4.2 Reference Verification（引用真实性核查）

目标是对**全部成功提取的文末参考文献**进行存在性核查，优先利用 DOI、标题、作者和年份与公开元数据匹配。逐条给出“匹配到文献”“元数据存在明显冲突”“未能核实”及来源，并显示 `已提取数 / 检查数 / 未核实数`。检索不到不能自动等于虚构；无法正确拆分的条目不得假装已检查。本轮**不逐篇阅读全文**，也不承诺判断被引论文是否支持正文论点。

### 4.3 Code & Reproduction Signals（代码与外部复现线索）

先检查论文、附录、随附材料及明确关联的官方页面／仓库，记录是否找到**可访问的**代码。正文没有链接不等于没有公开代码；所有来源均未找到时，应写“在已核查来源中未找到可访问的公开代码”，并列出来源和核查时间。

对明确关联的公开仓库，查看与论文结果有关的公开 issue／评论及作者回复、后续修复；区分“有人报告复现成功”“有人报告复现失败或数据问题”“仅有讨论，无法判断”“未发现相关反馈”。第三方评论是有来源的线索，不是系统亲自复现实验的结论。代码公开可提高这一维度评分，可信的独立成功复现记录可进一步提高；**第一版不运行代码，因此这一维度不授予代表亲自复现验证的满分**。没有外部评论不等于复现失败。

理论等不依赖可运行代码的论文，应允许此项不适用或调整判准。商业机密、隐私等不公开理由作为作者陈述和可核查性限制记录，不推断其欺骗意图。数据组需明确适用性与理由判准。

### 4.4 候选研究方向，不自动加入评分

结果数字自洽性、实验设置透明度及数据来源等可作为数据组的候选研究项。只有找到独立用户价值、可靠的论文内证据和可复查样本，才提交产品组决定是否成为新维度；两周计划不以“增加维度数量”为验收目标。

## 5. 结果页与评分原则

结果页优先显示总评、三个维度的小评分、低分项提醒和可展开的 Findings／Evidence。每条重要发现至少说明：具体判断、原文位置或外部 URL、它如何支持判断、获取时间、核查状态及不确定性。读者可以从总评直接回查到证据。

- 新功能采用“**分项评分 → 总评分 → 类别**”的结构；分数越高表示在已执行检查范围内证据越充分、风险越少。具体分值区间、权重、空值和类别阈值由数据组提出、产品组确认后进入字段合同，不在本稿编造。
- 总评根据适用维度汇总，**不设单项一票否决或总评级上限**。但任何明显偏低的分项必须在总评附近提醒，不能被高总分隐藏。
- D-039～D-040 已确认第一版主张维度采用去重后全部条目的最低有效分；各项有分时，总体按适用维度平均汇总并映射类别，不因单个重大问题另设评级上限。低分和重大／关键发现均须醒目提示。任一适用维度无法评分时，沿用 D-034 留空总分与类别，保留已确认发现和其他分项。
- 报告类别工作文案：`No significant concerns found`、`Some concerns`、`Significant concerns`、`Critical concerns`。类别只描述检查发现的风险，不使用 `Fraudulent`、`Suspected fraud` 或 `Research misconduct` 作为自动结论。
- 解析失败、外部服务失败等导致无法完成评估时使用独立的 `Unable to assess` 状态并解释技术原因，不能将其当成低风险或高风险。
- 系统可给出“谨慎阅读／引用”“暂不建议直接引用”等阅读决策提示，但需要说明触发它的具体分项与证据。建议不是论文真伪认证，也不是禁止阅读或引用的决定。
- “未发现明显问题”只表示**已完成的检查未发现**，不是对整篇论文的安全保证；须展示检查覆盖范围与限制。

## 6. 证据与误报控制

第一版宁愿把值得注意的线索提示给读者，也不希望明显有问题的论文被轻易标成“放心使用”。但提示要分层：低门槛线索可进入“待核查”，严重或确认性用语必须有更强证据。信息缺失、数据库未收录、仓库无讨论、匿名稿件和论文类型差异不能被悄悄转成欺诈事实。

论文内证据与外部证据必须分开标识。外部证据记录来源、论文／仓库匹配理由、抓取时间和当时状态；有作者解释、issue 关闭或后续修复时一并呈现。模型不得生成不存在的引用、评论、链接、页码或结果。无法确认则如实标记。

## 7. 验证与成功判断

数据组建立覆盖三类检查的人工核查样本，含明确问题、正常对照、争议／无法核实案例和不同 ML 论文类型。人工标注要记录原文、外部来源、核查时间、判断理由及标注分歧；不能用旧五维总分、论文录用结果或模型输出作为可信度真值。

阶段验收至少检查：重要风险遗漏、正常论文误报、每条发现的证据可回查性、引用检查覆盖率、外部来源匹配与状态是否正确、失败／不适用状态是否诚实，以及同一输入重复运行的结果可解释性。数据组提出可执行的衡量方式和样本量，产品组确认；不预设没有样本依据的准确率或固定阈值。分析交付完成与模型效果达标分别记录。

## 8. 不属于本轮

- 下载运行论文代码，复现实验、验证数值达到论文报告值或声称给出复现认证。
- 证明作者欺诈、判断主观动机、做学术不端裁决或替代正式审稿。
- 逐篇阅读全文核实每个引用对正文论点的支持；穷尽式全网搜索或保证发现所有代码和社区讨论。
- 基于 venue 的录用预测、官方审稿评分、全领域通用评估，以及把 SOTA 与可信度画等号。
- 旧五维评分的重新训练／大幅改版权重、与新可信度分数混算、历史结果展示和以 CSPaper 视觉模仿为主线的改版。
- 公网部署、账号付费、复杂权限和正式数据保留／隐私承诺；原型仍应避免意外公开上传文件。

## 9. 第二轮开始前必须确认的规则

1. 数据组依据已有[可信度核查 Rubric v0.1 评审稿](../03_过程与交付/数据样本与%20Rubric/可信度核查_Rubric_v0.1.md)，用真实样本验证三维适用性、分值、权重、总体类别、低分提醒和代码项边界；产品组批准后才成为正式规则。
2. 后端、前端、数据组评审已有的[独立可信度报告字段合同 v0.1 草稿](../01_统一规范/可信度核查报告字段合同_v0.1.md)；旧合同继续约束旧评分功能，不得把 ICLR `venue_id` 变成新功能准入条件。
3. 选定首批公开 ML 样本及正常对照、外部资料访问方式和降级行为；本地未公开 PDF 可输入，但不因缺少公开讨论自动扣为欺诈。
4. 非英文论文、非常规 PDF、无 DOI 引用、匿名稿件及无代码适用性在试验后分别说明覆盖与限制。
