## 一、本轮目标与交付边界

在第一轮已有输入页面、解析、模型调用、证据定位和五维报告的基础上，新增一个独立的 **Paper Credibility Check**。输入任意 venue 的可解析 ML 论文，返回总体风险类别、适用维度的小评分、可回查的风险发现和检查覆盖范围。旧五维评分保持可用，但不自动进入新报告或参与新总分。

两周交付必须实际覆盖三项检查：①摘要／引言关键主张与论文后文证据，②成功提取的全部文末引用的存在性，③代码公开情况与明确关联的公开仓库中复现讨论。不运行代码，不逐篇阅读全文验证被引文献，不声称证明作者欺诈。新颖维度只做证据驱动的研究候选，不因缺少第四维而判本轮失败。

## 三、工作包及交接

### 启动对齐与框架衔接

启动时围绕现有产品方向确认下表。输入、解析和基础服务共同使用；旧评分与新可信度核查分别创建任务、生成报告和计算分数。确认结果写入[决策记录](../03_过程与交付/决策记录.md)，执行人、日期和进度统一填写[交付任务清单](../03_过程与交付/第二轮_交付任务清单.md)。本节是交接提案，尚未代替跨组评审。

| 部分 | 执行口径 | 启动时需要确认的内容 |
|---|---|---|
| 共用基础 | 复用 arXiv／PDF 输入、私有上传、论文身份、解析、模型调用及证据定位；任务与轮询机制可复用，新旧状态按各自合同映射 | 实际代码版本、运行配置、真实论文的解析质量与证据位置 |
| 旧五维评分 | 保持旧入口、五维报告、v0.4 合同及原计分逻辑，作为回归对象 | arXiv、PDF、失败路径和原报告可用的验证记录 |
| 新可信度核查 | 独立入口、请求、报告及计分；检查主张、文末引用、代码与外部复现线索；新模式不要求 venue | 新合同版本、三维含义、来源与时间、覆盖率、空值及失败语义 |
| 评分规则 | 按现有 Rubric 评审稿开展标明版本的试验；正式规则经真实样本校准和审核后接入 | 分值、权重、类别阈值、低分提醒和无法出分条件；保留低分项不封顶总评的产品原则 |
| 额外旧工作 | 保留本机已做的历史报告保存、展示等改动，登记其版本与状态；本轮优先资源用于 R2C 的三维核查 | 哪些改动进入共享基线、哪些另行安排；历史展示不计为 R2C 核查完成 |

合同评审应一起查看正常、有明确问题、未核实、不适用和外部技术失败的响应示例。查询没有匹配、仓库没有相关讨论和查询失败须分别表达；未检查项标出实际范围。流程结束不等于所有事实已核实，适用项无法评分时遵循新 Rubric 的空值与汇总规则。

2026-10-01 启动讨论已明确：第一周优先打通**主张与论文证据对照**，引用与代码／仓库的技术验证并行。首个集成检查点是同一篇真实 ML 论文产生至少一条人工核对的主张发现，前端可回查主张和后文证据两端的位置；其他维度如实记录检查状态，旧评分仍按原合同可运行。这个检查点只验证基础衔接，不替代第二周三维集成和效果复评。

首批人工主张案例须包含论文 ID、版本或文件摘要、摘要／引言中的关键主张原文与位置、论文内证据原文与位置、实验条件及人工预期。第一周可先用单条主张验证链路，但须标明 scope_complete=false；摘要／引言关键主张的约定范围不能以该单条案例替代。预期区分支持、部分支持、未找到对应证据、明确冲突和无法判断；未找到证据时记录查找范围。同一指标、数据集、基线和条件的核对是判断依据，不能把不同条件下的数字差异直接标成冲突。案例填写已有[样本与复评记录](../03_过程与交付/数据样本与%20Rubric/第二轮_可信度核查样本与复评记录.md)，组内执行人及交付日期在任务主表维护。

数据组先提交首批人工案例及预期状态；后端用相同论文确认真实解析和来源获取；前端依据新合同绘制入口、结果层级及异常状态。引用与仓库的技术探测可以并行。首批交接物与评审记录齐备后，再据此细化组内日期。

### 产品组：先锁定用户承诺与验收口径

1. 确认本基线、三项维度、模式入口与报告文案；区分已决定的业务规则和待数据组验证的评分规则。
2. 组织数据、后端、前端对新报告合同评审；确认旧评分必须回归验证、但不进入新报告或与新分数混算，并核对每个发现的证据与状态展示。
3. 选择至少一条可演示的端到端路径，并审核正常、风险、未核实和技术失败案例；记录范围变更。
4. 将 client 的会议总结标记为来源，不把尚未签字的阈值或样本写成客户验收承诺。

### 数据组：给出可执行的判断依据，而非只比较旧五维分差

1. 建立覆盖三维的人工核查样本：有明确问题、无明显问题、争议／未核实；记录论文版本、原文位置、外部链接及核查时间。
2. 研究摘要／引言关键可验证主张的提取、去重、排除依据和遗漏检查，完善论文类型适用性、引用匹配冲突与代码／issue 线索的强弱；保留标注分歧与仲裁。
3. 用真实样本校准现有 Rubric v0.1 草稿的分值区间、权重、总分、四档英文类别、低分提醒和无法评估规则；**单项低分不限制总评级上限**，但提供其被总分掩盖的测试案例。代码维度的满分边界单独定义。
4. 对后端真实输出做重要风险漏报、正常样本误报、证据错误和覆盖率复评；将“分析交付完成”与“效果达到目标”分开记录。
5. 探索数字自洽性等第四维候选，交付样例、证据可得性和误报风险；是否纳入开发另行决定。

### 后端组：实现可追溯的检查链路

1. 核对已有通用 ML 输入、PDF、旧报告和失败路径，固定可回归版本；新核查复用现有解析，不把数据组 Manifest 当白名单。
2. 与数据组实现摘要／引言关键可验证主张提取、去重和论文内对照，输出每条判断的两端证据或明确的“未找到／无法判断”，记录读取范围与遗漏，不让模型虚构页码或表格。
3. 增加 references 条目提取、元数据匹配、候选消歧与逐条状态；记录总条目、可解析数、已检查数、未核实数。外部查询需缓存、限速并处理故障。
4. 查找论文明确关联的代码来源，确认仓库匹配，再检索与复现有关的公开 issue／评论及作者回复和修复状态。区分“第三方声称”与“系统实证”；不运行代码。
5. 按新合同生成总分、类别、分项、小提醒和证据来源。检查来源 URL、获取时间、空值、不适用与失败语义；不采信模型随意编出的总分。

### 前端组：让读者看懂风险而非只看一个分数

1. 保留旧评分入口，新增独立的 **Check Credibility** 流程；不要求用户先选择 ICLR，不在新模式展示旧五维分数。
2. 新结果页先给总体类别和总分，再给三个维度的小分数与低分提醒；每项可展开具体 Findings、论文位置、外部来源、核查时间和不确定说明。
3. 将“元数据未能核实”“没有复现讨论”“不适用”“技术检查失败”分开展示；不得把空值渲染为零分或“未发现问题”。
4. 用真实接口跑通 arXiv 和 PDF；旧评分关键路径回归。CSPaper 的视觉参考只用于必要可读性改进，不是本轮主要验收目标。

## 五、本轮完成定义

1. 用户可在旧评分与新可信度核查之间选择；两条路径对同一 ML arXiv／PDF 输入均有明确成功或失败结果，旧报告没有被新功能破坏。
2. 新报告实际检查三类来源，全部成功提取的文末引用都有逐条存在性状态；未提取、未查询、未匹配不得混写为“虚构”。
3. 关键风险能定位到论文原文或外部原始页面，外部发现标出核查时间；独立第三方复现反馈不被写成系统已复现。
4. 总分、小评分、四档类别及低分提醒按已确认 Rubric 一致生成；单项低分不封顶总分，但在页面可见。没有充分输入或技术失败时不生成伪确定结论。
5. 数据组以人工案例复评漏报、误报、证据错误和覆盖率，后端修复可复现的问题；无法解决的能力边界和剩余错误如实交付。
6. 文档、任务状态、演示样本、版本与验收证据一致。完成集成不等于宣称“能识别所有欺诈论文”。

## 六、风险与处理

| 风险 | 处理原则 |
|---|---|
| PDF references 拆分错误 | 显示提取覆盖率；低质量条目进入未检查／需人工确认，不制造虚构引用结论 |
| 文献数据库未收录或字段不一致 | 多字段匹配并保留候选与冲突理由；检索不到为未核实，不等于造假 |
| 找错同名代码仓库或被无关 issue 干扰 | 记录仓库与论文的关联依据；只展示与论文结果明确相关的讨论，并呈现作者回复 |
| 无代码、无评论的新论文被误判 | 只记录检查范围内的事实；区分适用性、透明度缺口与恶意推断 |
| 严重单项被平均总分稀释 | 遵照不封顶决定，但总分旁突出低分项和证据，验收专门测试此情形 |
| 两周内模型效果不稳定 | 优先保证真实来源、诚实状态和可复查报告；效果与分析交付分开验收，剩余问题入后续计划 |
