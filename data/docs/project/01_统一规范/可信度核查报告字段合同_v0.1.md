## 1. 通用约定与版本

- 字段使用英文 `snake_case`。下文表格列出的字段均必须出现；标 `?` 的类型允许值为 `null`，不是允许省略键。对象数组内部同样适用。
- 空数组表示该数组当前没有记录，不单独表达成功或未发现问题；必须结合适用性、完成状态和检查范围。
- 时间使用 UTC ISO 8601 字符串，例如 `2026-09-22T05:00:00Z`；数量是非负整数，比例在 0–1 内。比例最多保留 4 位小数，分母未知或为 0 时为 `null`。
- 报告中的 ID 在各自集合内唯一，跨表引用必须可解析。论文块 ID、来源 ID、引用条目 ID 与 finding ID 是不同对象，不互相代替。
- 原始上传路径、访问密钥、堆栈不进入报告。外部 URL 是实际使用的来源，不能由模型编造。
- 同一请求固定 schema、Rubric、解析、提示词和流水线版本。规则变动发布新版本，不用当前规则重写旧报告；schema 不兼容时明确拒绝读取或创建，不猜测字段含义。
- `rubric_version=0.1-draft` 必须搭配 `rubric_status=draft` 与 `is_provisional=true`。草案规则的数值只用于标明版本的试验，不能宣称已经校准或经 client 验收。
- `data_origin=synthetic` 表示示例／合成数据，前端显式显示示例标识；真实检查用 `live`。真实调用失败不得回退合成结果。

## 2. 输入、接口与兼容方案

建议新增独立资源，避免改动旧 `/v1/assessments` 的五维合同：

| 接口 | 建议行为 | 实现状态 |
|---|---|---|
| `POST /v1/credibility-assessments` | 接收新请求，返回 HTTP 202 与完整的排队状态对象 | 待开发 |
| `GET /v1/credibility-assessments/{assessment_id}` | 返回同形状任务快照；运行中供前端轮询，完成后读取报告 | 待开发 |
| `POST /v1/uploads` | 复用现有 PDF 上传，取得 `upload_id`；上传本身不生成可信度结果 | 本地代码已有，兼容性仍需回归 |
| `GET /v1/models` | 复用可用模型目录；创建时验证所选模型实际可用 | 复用现有能力，需联调 |

单项重试及历史查询不在本合同新增接口。v0.1 可用重新创建任务重试；新任务取得新 ID，可复用有版本／时间标识的有效缓存。服务端限流与重试不会自动改成另一模型而不记录。

外部故障后的终态页面须提供“新建任务重试”按钮：复用原输入与用户选择创建新任务，保留原运行 ID 和结果，不覆盖旧报告；若原版本或模型已不可用，明确提示并让用户重新选择，不静默替换。此按钮重跑整个核查流程，不要求新增单维重试接口。

创建请求字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `schema_version` | string | 固定本稿版本 |
| `analysis_mode` | string | 固定 `credibility` |
| `source` | Source | 输入来源，定义见下 |
| `model_id` | string | 从当前可用模型目录选择，不能由示例推定已开通 |
| `rubric_version` | string | 本稿为 `0.1-draft`；服务端只接受其已实现的版本 |

`Source` 固定为 `{type, arxiv_id, upload_id}`：`type=arxiv` 时 `arxiv_id` 为非空规范 ID、`upload_id=null`；`type=pdf` 时相反。页面可接受 arXiv URL，但在提交前解析为 ID；服务端仍须校验。未指定版本的 arXiv ID 解析后必须在 Paper 记录实际版本。请求不包含 `venue_id`，也不允许从旧请求静默推断可信度模式。

错误语义：400 为业务不支持的 schema／Rubric／模型版本，422 为字段或输入格式不合法，404 为任务或上传 ID 不存在，429 为本服务限流，503 为暂时无法受理。错误响应为 `{"error": ErrorInfo}`；不能返回 HTTP 成功配一份假报告。具体输入格式校验与大小限制复用已有能力，不在本文编造已经支持的新限制值。

```json
{
  "schema_version": "credibility-0.1.0-draft",
  "analysis_mode": "credibility",
  "source": {"type": "pdf", "arxiv_id": null, "upload_id": "upload_example_only"},
  "model_id": "model_standard_v1",
  "rubric_version": "0.1-draft"
}
```

此请求是格式示例，`upload_example_only` 不是可调用的上传记录。

## 3. 顶层任务对象 CredibilityAssessment

| 字段 | 类型 | 含义 |
|---|---|---|
| `schema_version` | string | 本合同版本 |
| `analysis_mode` | string | 固定 `credibility` |
| `assessment_id` | string | 本次运行唯一标识 |
| `data_origin` | enum | `live`／`synthetic` |
| `source` | Source | 原请求中的输入 |
| `model_id` | string | 所选产品模型 ID |
| `status` | enum | `queued`／`processing`／`completed`／`failed` |
| `stage` | enum | `queued`／`retrieving`／`parsing`／`checking`／`finalizing`／`done`／`failed` |
| `progress_percent` | integer | 0–100，运行进度估计，不是检查覆盖率 |
| `created_at` | timestamp | 受理时间 |
| `started_at` | timestamp? | 开始执行时间 |
| `completed_at` | timestamp? | 终态时间，包括失败 |
| `paper` | Paper? | 解析后实际输入的身份与质量 |
| `report` | CredibilityReport? | 终态报告；排队／运行时为 null |
| `warnings` | Notice[] | 运行与能力限制；无警告时为空数组 |
| `error` | ErrorInfo? | 整个任务失败时的原因，其他状态为空 |

状态关系：

1. `queued`：`stage=queued`，进度 0，`started_at/completed_at/paper/report/error=null`。
2. `processing`：`started_at` 有值，`completed_at/error/report=null`，进度 0–99；页面展示阶段、进度和运行提示，终态前不展示分项结论或正在计算的临时分数。
3. `completed`：`stage=done`，进度 100，完成时间、Paper 和 Report 必须存在；表示流水线已结束，不保证所有来源已核实，也不等于论文低风险。
4. `failed`：`stage=failed`，`completed_at/error` 有值；解析前失败可没有 Paper／Report。若已有可保存的部分报告，可保留，但总体必须无法评估。失败不将进度强行置为 100。
5. 单个外部服务失败通常结束为 `completed` 加部分报告，维度状态为 `partial/failed`；非 ML、无法解析或无法生成有效报告才使用任务级失败。

`Paper` 字段：`paper_id:string`、`title:string?`、`arxiv_id:string?`（真实 arXiv 输入须带实际版本）、`source_sha256:string`（实际 PDF 的 SHA-256）、`page_count:integer>=1`、`language:string?`、`parse_quality:good|partial|poor`。同名论文不能替代文件摘要或版本标识；合成示例使用显式示例身份和占位摘要，不当真实来源。

`ErrorInfo`：`code:string`、`message:string`、`retryable:boolean`、`debug_id:string?`。建议稳定错误码：`INPUT_INVALID`、`UNSUPPORTED_VERSION`、`MODEL_UNAVAILABLE`、`UPLOAD_NOT_FOUND`、`OUT_OF_SCOPE`、`PARSE_FAILED`、`MODEL_FAILED`、`REPORT_INVALID`、`SERVICE_UNAVAILABLE`。具体 HTTP 状态与任务级错误不混为风险评级。

`Notice`：`code:string`、`message:string`、`dimension_id:DimensionId?`。例如 `PARTIAL_PARSE`、`EXTERNAL_QUERY_FAILED`、`EXTRACTION_COVERAGE_UNKNOWN`、`DRAFT_RUBRIC`。

| `rubric_id` | string | 固定 `paper_credibility` |
| `rubric_version` | string | 本稿为 `0.1-draft` |
| `rubric_status` | enum | `draft`／`approved`；本稿只能是 `draft` |

| `generated_at` | timestamp | 此报告汇总时间 |
| `dimensions` | Dimension[3] | 固定三维，顺序见下 |
| `checks` | Checks | `{claims, references, code}` 三个详细对象 |
| `evidence` | Evidence[] | 论文内与外部证据池 |
| `sources` | ExternalSource[] | 外部访问与缓存来源记录，失败访问也要保留 |
| `findings` | Finding[] | 有证据的风险、待核实线索及必要上下文 |
| `overall` | Overall | 确定性总分、类别、排除项及解释 |
| `alerts` | Alert[] | 低分、重大问题、覆盖缺口 |

`Versions`：`pipeline_version:string`、`parser_version:string`、`prompt_version:string`、`model_calls:ModelCall[]`。每个 ModelCall 为 `{purpose:string, provider:string, model_version:string}`，按实际调用去重记录；未调用模型时数组为空且在限制中说明。不能用当前默认模型配置冒充实际调用版本。

## 5. 三维状态 Dimension

`DimensionId` 固定顺序：`claim_evidence`、`reference_verification`、`code_reproduction`。Checks 的 `claims/references/code` 分别对应这三个 ID。

| 字段 | 类型 | 规则 |
|---|---|---|
| `dimension_id` | DimensionId | 固定 ID |
| `applicability` | enum | `applicable`／`not_applicable`／`undetermined` |
| `applicability_reason` | string | 适用性依据，不可为空 |
| `check_status` | enum | `not_run`／`running`／`completed`／`partial`／`failed` |
| `score_status` | enum | `pending`／`scored`／`unable_to_assess`／`not_applicable` |
| `score` | number? | 0–10；代码不超过 9；本稿分项是整数 |
| `weight` | number | 原始权重，本稿均为 1；不是已经归一化的比例 |
| `score_rule_ids` | string[] | 实际触发的 Rubric 规则；无法评分或不适用为空 |
| `summary` | string | 说明事实、证据和限制，不能仅重复分数 |
| `unassessed_reason` | string? | `pending/unable_to_assess` 时必填，其他状态为空 |
| `evidence_ids` | string[] | 支持该维度判断与适用性的证据 |
| `finding_ids` | string[] | 该维度有关发现 |

硬约束：

- `scored` 必须适用、检查完成、分数非空、证据非空，详细对象通过 Rubric 的范围及条目门槛。分数必须由规则计算。
- `not_applicable` 必须适用性同名、`check_status=not_run`、分数为空、规则为空，理由和依据必须存在；指此维度的实质检查未执行，适用性判断已执行。
- `undetermined` 必须为空分；终态为 `unable_to_assess`。非终态可 pending。
- `partial/failed` 不能有分数。全部查询结束但仍有未核实项，可为 `check_status=completed` 与 `score_status=unable_to_assess`，不把“流程结束”混为“已核实”。
- 终态不能出现 `running/pending`；未执行完的剩余条目明确记 `not_checked`，维度改为 partial 或 failed。

## 6. 证据、外部访问和发现

### 6.1 Evidence

| 字段 | 类型 | 规则 |
|---|---|---|
| `evidence_id` | string | 证据 ID |
| `origin` | enum | `paper`／`external` |
| `mode` | enum | `quote`／`paraphrase` |
| `excerpt` | string | 原文或忠实概述；不能用不存在的文字凑证据 |
| `paper_locator` | PaperLocator? | 论文内证据必填，外部证据为空 |
| `source_id` | string? | 外部证据必填，对应获取成功的来源；论文内为空 |
| `location_confidence` | enum | `high`／`medium`／`low`；不高于解析或来源定位质量 |

`PaperLocator`：`page_start:integer>=1`、`page_end:integer>=page_start`、`chunk_id:string`、`section_title:string?`、`element_label:string?`。页码使用文件中的 1 起始物理页序，不猜测印刷页码。表格／图像证据仍要能映射真实位置；`element_label` 存在不代表数值读对。

`quote` 必须在对应文本块或外部快照内核实，而非只在整篇论文中查到即可。`paraphrase` 不要求逐字相同，但必须人工或程序可回查其支持关系。关键证据校验失败时，相应条目改无法判断，不继续保留依赖它的分数。

### 6.2 ExternalSource

| 字段 | 类型 | 规则 |
|---|---|---|
| `source_id` | string | 本次报告来源记录 ID |
| `kind` | enum | `metadata`／`supplement`／`project_page`／`repository`／`discussion_listing`／`issue`／`comment` |
| `url` | string | 实际查询或页面 URL；对外可显示，不含凭据 |
| `fetch_status` | enum | `ok`／`not_found`／`access_denied`／`timeout`／`rate_limited`／`error` |
| `http_status` | integer? | 有 HTTP 响应时记录，否则为空 |
| `retrieved_at` | timestamp | 本任务读取该来源或缓存的时间 |
| `observed_at` | timestamp | 原内容实际获取／请求失败发生的时间；缓存不得伪装刚抓取 |
| `is_cached` | boolean | 是否复用缓存 |
| `snapshot_ref` | string? | 内部可追溯的响应／快照标识，不是服务器本地路径；成功访问必填 |
| `association_reason` | string | 为什么查询它，它与条目／论文／仓库的关系；不等于已经确认关联 |

`not_found` 表示该次请求的来源状态，不自动决定引用为虚构或代码未公开。查询正常返回空候选属于 `fetch_status=ok` 与条目 `unverified`。失败来源可被条目的 `source_ids` 引用，但不能作为成功抓取的外部 Evidence。

### 6.3 Finding 与 Alert

`Finding` 全字段：`finding_id:string`、`dimension_id:DimensionId`、`item_ids:string[]`、`kind:concern|verification_gap|context`、`severity:info|minor|moderate|major|critical`、`certainty:confirmed|reported|unresolved`、`title:string`、`detail:string`、`evidence_ids:string[]`、`source_ids:string[]`、`limitations:string[]`。

`item_ids` 指对应维度的 claim／reference／repository／discussion ID；维度级缺口可为空。已确认风险必须有有效证据；技术故障类 gap 可以只有失败来源及原因。第三方复现线索使用 reported，不能写 confirmed 实验结果。一个 finding 不直接加减分，计分走对应条目规则，避免同一问题重复扣分。

条目结果的最低提示强度建议：`C_PARTIAL/R_MINOR_CONFLICT` 为 minor；`C_NO_SUPPORT/K_NOT_FOUND` 为 moderate（后者为材料缺口）；`C_CONTRADICTION/R_MAJOR_CONFLICT/K_CORROBORATED_FAILURE` 为 major；`C_CORE_CONTRADICTION` 为 critical。未知和技术失败为 gap，不凭失败本身升级风险严重性。

`Alert`：`type:low_dimension_score|material_finding|assessment_gap`、`dimension_id:DimensionId`、`finding_ids:string[]`、`message:string`。同维度低分及缺口各最多一条；重大 finding 可以合并引用，但不能隐藏。前端展示服务端生成的提醒，不自行重算或删掉。

引用有效查询后仍无可靠匹配时，必须保留 `verification_gap`、`certainty=unresolved` 的 finding，并生成引用维度的 `assessment_gap`，在总评附近醒目显示“引用存在性待核实，建议复核”，可展开查看条目、查询来源和原因。提醒的醒目程度不代表错误已确认；不能仅凭无匹配升级为已确认错误、虚构引用或强制扣分。

## 7. Checks.claims

| 字段 | 类型 | 含义 |
|---|---|---|
| `selection_scope` | string | 从哪些部分选择了什么主张，以及重要排除项 |
| `scope_complete` | boolean | 本次约定范围是否充分核查，包含重要主张是否遗漏 |
| `scope_limitations` | string[] | 解析缺失、排除范围等 |
| `items` | ClaimItem[] | 纳入检查的主张 |

`selection_scope` 必须说明摘要／引言关键主张的选择范围、原文位置、排除理由与遗漏；证据检索记录正文、图表和附录的查找范围。重复主张去重，不以固定条数代替范围完整。未检查的已提取条目保留 not_checked；影响选定主张的读取或遗漏缺口写入 scope_limitations，scope_complete=false。不要求提取正文每条主张，也不宣称全文核查完整。

`ClaimItem` 全字段：

- `claim_id:string`，`statement:string`，`importance:core|supporting`。
- `conditions:string`：数据集、指标、基线、限制条件；没有明确条件时写明原因。
- `claim_evidence_ids:string[]`：主张原文位置；必须非空。
- `comparison_evidence_ids:string[]`：对应支持／反证的位置；supported、partial、contradicted 必须非空；not_found 可为空，但 search_scope 必须充分。
- `search_scope:string`，`outcome:supported|partially_supported|not_found|contradicted|unable_to_determine|not_checked`，`reason:string`。
- `score_rule_id:string?`，`item_score:number?`：使用 Rubric 第 3 节。不能由前端自由填写。

维度 scored 必须 scope_complete=true、items 非空、每条有有效分。条目 min 与 Dimension.score 一致；强冲突必须有两端证据和条件一致说明。维度不适用时 items 为空、scope_complete=false，并以 Dimension 中的适用性证据解释；不得展示为完整检查。

## 8. Checks.references

| 字段 | 类型 | 含义 |
|---|---|---|
| `extraction_status` | enum | `complete`／`partial`／`failed`／`not_applicable` |
| `extraction_reason` | string | 边界、分割、缺口判断的依据，不能只写“解析成功” |
| `original_total` | integer? | 原文总条目数；未知为空 |
| `extracted_count` | integer | 成功提取条目数量，等于 items 长度 |
| `checked_count` | integer | 获得有效查询结果并作出 matched/conflict/unverified 判断的条目数 |
| `matched_count` | integer | matched 数量 |
| `conflict_count` | integer | metadata_conflict 数量 |
| `unverified_count` | integer | unverified 数量；无结果但有效查询已完成也计入 |
| `not_checked_count` | integer | not_checked 数量，含无法执行的查询 |
| `query_completion_ratio` | number? | checked / extracted |
| `extraction_coverage_ratio` | number? | extracted / original_total，未知分母为空 |
| `gaps` | string[] | 未拆分片段及其他提取缺口，保留位置说明 |
| `items` | ReferenceItem[] | 全部成功提取条目，不用查询限额静默截断 |

`ReferenceItem` 全字段：`reference_id:string`、`raw_text:string`、`paper_evidence_ids:string[]`、`parsed:BibliographicMetadata`、`outcome:matched|metadata_conflict|unverified|not_checked`、`reason:string`、`source_ids:string[]`、`candidates:ReferenceCandidate[]`、`selected_candidate_id:string?`、`score_rule_id:string?`、`item_score:number?`。

`BibliographicMetadata`：`title:string?`、`authors:string[]`、`year:integer?`、`doi:string?`、`arxiv_id:string?`。未知作者用空数组，不造作者。

`ReferenceCandidate`：`candidate_id:string`、`metadata:BibliographicMetadata`、`source_id:string`、`evidence_ids:string[]`、`match_basis:string`。matched 必须选择一个有来源的候选；conflict 必须保留能说明冲突的候选／来源。unverified 可有多个候选但 selected_candidate_id 为空。标识冲突和版本差异的处理见 Rubric，不按字符串相似度单独定性。

计数不变量：

```text
checked_count = matched_count + conflict_count + unverified_count
extracted_count = checked_count + not_checked_count = len(items)
如果 original_total 已知：extracted_count <= original_total
```

发现 extracted_count 超过人工确认总数时，先解决重复拆分／总数错误，不强行把比例截断为 1。全部提取条目查完不等于原文无遗漏。`original_total=0` 只有确认原文无引用时可用；真实无引用时维度不适用、extraction_status=not_applicable、所有计数为 0、两种比例均为空。

## 9. Checks.code

| 字段 | 类型 | 含义 |
|---|---|---|
| `scope_complete` | boolean | 约定的来源与相关讨论范围是否完成 |
| `scope_limitations` | string[] | 搜索、关联、分页及版本限制 |
| `searches` | CodeSearch[] | 论文、附录、补充材料及发现的外部来源各自查了什么 |
| `code_availability` | enum | `available`／`not_found_in_scope`／`unable_to_verify`／`not_applicable` |
| `reproduction_signal` | enum | `success_reported`／`failure_reported`／`discussion_only`／`no_feedback_found`／`unable_to_verify`／`not_applicable` |
| `repositories` | Repository[] | 候选仓库及关联依据，包括需要排除的候选 |
| `discussions` | Discussion[] | 与筛选判断相关的讨论及排除理由 |
| `base_score_rule_id` | string? | K_NOT_FOUND、K_AVAILABLE 或 K_INDEPENDENT_SUCCESS；无法评分或不适用为空 |
| `score_rule_id` | string? | 最终规则；负面条件成立时为 K_CORROBORATED_FAILURE，否则同基础规则 |

`CodeSearch`：`scope_id:string`、`scope_type:paper_body|appendix|supplement|project_page|repository|discussion_list`、`outcome:checked|not_present|not_applicable|failed|not_checked`、`reason:string`、`evidence_ids:string[]`、`source_ids:string[]`。适用代码检查至少记录正文、附录、补充材料三个入口；not_present 要说明如何确认不存在，不能用于资源访问失败。发现项目页／仓库后增加对应记录。

`Repository`：`repository_id:string`、`source_id:string`、`association:confirmed|uncertain|rejected`、`association_reason:string`、`association_evidence_ids:string[]`、`availability:accessible|inaccessible|unknown`、`implementation_evidence_ids:string[]`、`inspected_revision:string?`。确认关联必须有证据；accessible 指实际读到相关实现，而不只是链接能打开；不能因此声称运行过代码。

`Discussion`：`discussion_id:string`、`repository_id:string`、`source_ids:string[]`、`evidence_ids:string[]`、`signal:success_reported|failure_reported|discussion_only`、`relevance:relevant|irrelevant|undetermined`、`independence:independent|author|unknown`、`conditions:string`、`resolution:open|resolved|disputed|unknown`、`author_response_source_ids:string[]`、`scoring_eligible:boolean`、`reason:string`。resolution=resolved 要有解释或修复证据，不能只看 issue 关闭。scoring_eligible 的真假都需理由；有计分相关争议时不能直接标 false 再给高分。

no_feedback_found 必须在确认的来源范围内完成查询；无仓库可查时写明范围，不能暗示已经搜索全网。K_INDEPENDENT_SUCCESS 至少对应一条独立、相关、有条件说明的成功反馈。K_CORROBORATED_FAILURE 的作者确认或独立反馈要求按 Rubric 执行；最终结论仍是第三方报告。

不适用代码检查时：code_availability 与 reproduction_signal 均为 not_applicable，scope_complete=false，searches/repositories/discussions 为空，两个规则 ID 为空；依据保留在 Dimension 中。

## 10. Overall 与前端行为

2026-10-01 启动讨论已确认总体出分口径：任一适用维度无法评分，总分与总体类别留空；保留已确认发现和其他已评分维度，有证据的重大风险仍需提醒。真正不适用的维度才可从计算中排除。该确认见[决策 D-034](../03_过程与交付/决策记录.md)，不代表权重、分值或类别阈值已完成校准，也不代表新接口已实现。

`Overall` 全字段：`status:assessed|unable_to_assess`、`score:number?`、`category:string?`、`summary:string`、`unassessed_reason:string?`、`calculation:Calculation`。

`Calculation`：`method:string`（固定 `equal_weight_applicable_dimensions`）、`included_dimension_ids:DimensionId[]`、`excluded_dimension_ids:DimensionId[]`、`blocking_dimension_ids:DimensionId[]`、`assessed_dimension_count:integer`。

- included 为本应参与总体计算的 applicable 维度，包括暂时无法评分者；excluded 只含已确认不适用者；undetermined 不进入这两组，列入 blocking。
- blocking 为 applicable 中 score=null 的维度，加所有 undetermined。assessed_dimension_count 只计算已评分维度数，不等于 included 长度。
- blocking 非空或 included 为空时，overall.score/category=null，status=unable_to_assess，unassessed_reason 必填。不得对剩余有分维度另算一个假总分。
- 否则按 Rubric 第 6 节计算，category 只能是 no_significant_concerns／some_concerns／significant_concerns／critical_concerns；unassessed_reason=null。
- 如果已有范围缺口但不影响本规则允许的评分（例如原文引用总数未知、提取质量检查通过），在 limitations 明确说明；本稿的草案标识始终保留。

前端按“总评与提醒 → 三维状态／分数 → 条目与证据 → 覆盖范围和限制”展示。null 显示无法评估或不适用，不能显示 0 分。外部证据显示实际 observed_at，缓存可额外显示 retrieved_at。第三方反馈保留上下文和作者回复；高总分旁仍展示低分和重大 finding。

D-040 确认低分或重大／关键 finding 不改变平均汇总后的总分与类别；不能由前端另设评级上限。分项最低分按 D-039 及 Rubric 的完整性门槛执行，不能跳过无法评分条目。具体数值、权重和类别阈值仍取实际使用且明确标识的规则版本。

## 12. 异常与边界响应约定

### 边界状态的业务含义

下表沿用本合同与 Rubric 的条目及检查状态，供数据、后端和前端共同评审。情景为说明用例，不是已完成的真实人工样本。分项分数为空时，页面展示原因；总分如何处理以第 10 节和实际批准的 Rubric 版本为准。

| 业务情景 | 数据组记录的依据 | 后端条目与检查状态 | 页面说明与处理 |
|---|---|---|---|
| 未核实：引用查询成功，但没有足够依据确定对应作品 | 原始引用、查询来源与时间、候选及无法确认原因 | reference.outcome=unverified；查询已有效执行，可计 checked；条目和引用维度分数为空；生成 unresolved 的 verification_gap 与 assessment_gap | 总评附近醒目提示“引用存在性待核实，建议复核”，可展开来源、候选和原因，保留已核实结果 |
| 不适用：纯理论论文没有程序或实验依赖 | 论文类型、结论性质及代码项不适用的原文依据 | applicability/score_status=not_applicable；check_status=not_run，分数为空 | 显示“不适用”及依据；只有这种经确认的不适用项可从总体计算排除 |
| 技术失败：GitHub 超时，或必要表格无法可靠解析 | 访问失败或解析缺口记录；说明哪项材料未取得 | 来源 timeout／error 或相关检查 partial／failed；无法有效执行的条目 not_checked，必要材料不足的主张 unable_to_determine；受影响维度分数为空 | 显示“检查未完成”及原因，保留其他发现；可恢复时提供重新创建任务的重试路径 |
| 尚未检查：第一周只接通主张链路，引用和代码尚未运行 | 明确本次执行范围与未执行项 | 条目 not_checked；若任务已结束，未完成维度 partial／failed、score_status=unable_to_assess，不保留 running／pending | 显示“尚未检查”，不要把空数组解释为无风险或自动不适用 |
| 有依据的缺证：必要章节与附录可读，充分检索后仍找不到主张对应支持 | 主张原文、条件、查找范围与人工判断；说明排除了哪些解析问题 | claim.outcome=not_found；满足 Rubric 的完整性门槛后可按 C_NO_SUPPORT 计分 | 显示“在已检查范围内未找到支持证据”；有直接反证才使用“冲突” |

对优先开发的主张链路，必须区分最后一行与技术失败：查找充分但未找到支持，是有边界的检查结论；表格读不清或关键附录缺失，则无法判断。数字对照先确认数据集、指标、基线和实验条件；不同条件下的数字差异不能直接作为反证。

### 字段与汇总的边界变化

以下是对第 11 节完整对象的变更说明，不是省略字段的完整 API 响应。实现时仍返回全部规定字段，并同步更新关联计数、规则、证据、finding 和提醒。

| 场景 | 条目及维度变化 | 顶层／总评预期 |
|---|---|---|
| 引用成功检索但无匹配 | reference.outcome=unverified，候选与选中值按实填，item_score/规则为空；matched=0、unverified=1、checked=1；引用 check_status=completed、score_status=unable_to_assess、score=null、score_rule_ids=[] | status=completed；overall 无法评估，引用进入 blocking；增加 assessment_gap；不能写虚构引用 |
| 引用查询超时，没有其他有效候选来源 | 来源 fetch_status=timeout；条目 not_checked，checked=0、not_checked=1、查询完成率0；引用 failed 或部分成功时 partial，分数为空 | 任务可 completed；总评无法评估；失败请求不算已检查，不新增假外部证据 |
| 仓库查询失败 | code.scope_complete=false、相应 search=failed；availability/signal=unable_to_verify，规则为空；代码维度 failed/partial 且分数为空 | 其他维度保留；总分为空；error=null，失败以 sources、finding、warning 和 alert 表达 |
| 纯理论论文代码不适用 | 适用性证据有值；Dimension 与 Checks.code 按第 5、9 节置不适用 | excluded 包含代码，blocking为空；其他两维10分时总体10.0，仍不代表已复现 |
| 一条核心主张直接被反证 | 主张 outcome=contradicted、规则 C_CORE_CONTRADICTION、item_score=0；主张维度0分，有 critical finding 及双端证据；引用10、代码9须有各自依据 | 总分6.3、some_concerns；必须出现 low_dimension_score 与 material_finding，不封顶总评 |
| PDF 解析失败 | paper/report 可为空 | status=failed、stage=failed、error.code=PARSE_FAILED；完成时间有值，不产生风险类别 |
| 非 ML 输入 | 记录门控依据，未执行可信度检查 | status=failed，error.code=OUT_OF_SCOPE；不触发旧评分或 Mock |
| schema／Rubric 不支持 | 不创建新任务 | HTTP 400 与 ErrorInfo；不自动降级到旧五维合同 |

queued 与 processing 快照只填已知事实，report=null；页面先显示进度，终态再展示报告。终态有部分报告时，未完成对象保留明确信息缺口，不能把空数组渲染为没有风险。外部故障不清空已确认发现或其他分项，受影响分项与总分／类别为空，并保留新建任务重试入口。

## 13. 实现校验与联调检查

1. 新旧 schema 与入口隔离；旧输入、报告及证据回归不受破坏，新模式无 venue 必选。
2. 检查类型、必填、可空、枚举、ID 唯一性与所有跨对象引用；未知字段或未知版本明确报错。
3. 论文证据必须落到对应块和页；外部 evidence 只能引用 fetch_status=ok 的实际来源；引文与来源快照一致。
4. 引用计数与 items 逐条状态一致，分母未知为空，异常比例不静默修正。
5. 每个 item_score 与 score_rule_id 相符；维度、总分、类别和提醒用同一 Rubric 确定性计算。
6. 不适用、无法判断、未执行、技术失败分别校验；适用项失败不能从分母排除。
7. 所有 scored 维度通过详细范围门槛；代码最高9分；第三方反馈不得改写成系统亲自复现。
8. 报告使用草案时 provisional=true；示例与真实结果有明确来源标识；历史版本不自动改写。
9. 跑通 Rubric 的 T01–T15，并将真实样本与联调结果填写到已有复评和验收文档。通过合成例不等于模型效果通过。

报告校验失败时可进行有上限的修复或将受影响条目降为无法判断；修复不得添加不存在的证据。无法形成结构合法且语义诚实的报告时返回 REPORT_INVALID。
