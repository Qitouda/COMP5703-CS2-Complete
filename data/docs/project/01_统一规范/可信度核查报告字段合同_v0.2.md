# 可信度核查报告字段合同 v0.2

版本：`credibility-0.2.0-draft`，2026-10-19，BE-07 本地实现合同。沿用 [v0.1](可信度核查报告字段合同_v0.1.md) 的论文、三项检查、来源、证据及评分对象，补充执行质量和工具核查信息。该版本仍是草稿；本地实现及真实技术运行不等于已完成跨组／人工验收或部署。

## 1. 版本及兼容

接口保持 `POST /v1/credibility/assessments` 和 `GET /v1/credibility/assessments/{id}`。

- 请求 `schema_version="credibility-0.2.0-draft"` 时，响应使用同一版本，并返回本合同新增字段。
- 显式请求 `credibility-0.1.0-draft` 仍被接受，响应保留旧形状，不向该调用方添加 `coverage / execution / external_review`。数据库内部可保存完整执行记录，内部保存形状与旧版公开序列化分别处理。
- `schema_version` 描述传输结构，`rubric_version` 描述数值规则，两者分别维护。当前试验计分使用 `0.2-provisional-complete`；显式旧 `0.1-draft` 保持无分行为。
- 旧五维 `/v1/assessments` 不受本合同影响。不得把本合同的来源证据当作旧五维的论文内证据。

```json
{
  "schema_version": "credibility-0.2.0-draft",
  "analysis_mode": "credibility",
  "source": {"type": "arxiv", "arxiv_id": "2106.09685v2", "upload_id": null},
  "model_id": "model_standard_v1",
  "rubric_version": "0.2-provisional-complete"
}
```

## 2. 分项故障及任务终态

任务仍只使用 `queued / processing / completed / failed`，不新增公开 `partial` 任务状态。
`completed` 表示流水线已汇总，可同时包含 `failed / partial` 分项；这些分项的原因、覆盖和试验回退分必须保留。
论文无法解析或无法形成有效报告时使用任务级 `failed`，已有内部产物保留用于诊断／恢复。

模型失败不能回退到 prepared 主张或伪造成功结果。失败模型尝试与已验证模型结果分别留档；没有有效主张时不得声称主张核查成功。
GET 仅查询持久化快照，不重试模型或外部服务。重启后继续可查；恢复通过显式内部操作执行，不在本文声明新的公开重试端点。

## 3. Report 新增字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `coverage` | Coverage[3] | 按主张、引用、代码顺序解释实际核查范围与缺口 |
| `execution` | ExecutionSummary | 实际并发及各分支执行／复用信息 |
| `external_review` | ExternalReview? | 代码外部证据模型判断；未启用可为 null |

### Coverage

| 字段 | 类型 | 规则 |
|---|---|---|
| `dimension_id` | 既有三维 ID | 与对应分项一致 |
| `check_status` | 既有检查状态 | 保留执行／覆盖状态 |
| `scope_complete` | boolean | 当前已声明范围是否完整；有分数不强制为 true |
| `population` | enum | `selected_claims / extracted_references / bounded_repository_search` |
| `inspected_count` | integer ≥ 0 | 该统计范围内实际检查数量 |
| `total_count` | integer? ≥ 0 | 分母未知时为 null |
| `completion_ratio` | number? 0–1 | 不以部分可见材料推定论文全文覆盖 |
| `extraction_coverage_ratio` | number? 0–1 | 引用提取范围指标，未知为 null |
| `outcomes` | object<string,integer> | 原始结果计数，例如 supported、not_checked、confirmed |
| `confirmed_concern_count` | integer ≥ 0 | 有证据且已确认的 concern 数量；模型未审判断不自动升级 |
| `unresolved_count` | integer ≥ 0 | 当前可计数对象中的未知／未查项，不代表论文全部未知数量 |
| `technical_failure_count` | integer ≥ 0 | 失败来源观察及分项／外部模型失败记录数量；不是供应商 HTTP 重试次数 |
| `fallback_rule_ids` | string[] | 当前分数中与不足／无法核实相关的规则 ID |
| `limitations` | string[] | 具体范围、解析及来源限制 |

例如“15 条已选主张均已检查”只能描述所选主张；不能据此声明论文所有陈述均已检查。仓库总数／全网覆盖未知时不填 100%。

### ExecutionSummary

`execution={workers:integer, checks:object}`。`workers` 为实际配置的分支并发上限（1～3）；
`checks` 的固定键为 `claim_check / reference_check / code_check`。每项包括：

- `status`：`completed / partial / failed`，描述该执行步骤，不覆盖分项材料范围语义。
- `reused`：boolean，是否完整复用了已持久化且版本匹配的阶段。
- `elapsed_seconds`：非负数，本次读取／执行该分支的实际耗时。
- `error`：失败时的安全错误代码及 `retryable`，不返回密钥或原始供应商请求。

例如代码执行步骤可为 completed，但其有界搜索的 `scope_complete` 仍为 false。
恢复未保存的外部模型响应可能发生新的供应商调用，不能承诺第三方恰好调用一次。

### ExternalReview

| 字段 | 类型 | 含义 |
|---|---|---|
| `mode` | `native_tools / prefetch` | 实际采用的方式，禁止静默混同 |
| `status` | `completed / not_needed / failed / unsupported / partial` | 模型解释完成、无需额外解释或未完成 |
| `audit_ref` | string? | 模型输入、工具及输出审计的不可变快照引用 |
| `warnings` | string[]? | 范围及校验限制 |
| `base_facts_reused` | boolean? | 本次是否复用已保存且完整的基础采集结果 |
| `reason / error_code` | string? | 预算耗尽、能力不足或故障的安全原因 |

`completed` 不意味着所有复现讨论已穷尽，仍查看范围限制。`not_needed` 表示按声明的触发条件没有待模型处理对象，不伪装发生过模型调用。
`failed / unsupported / partial` 不算该新增语义核查功能验收通过，即使三项试验分及总分已经返回。

## 4. 来源及模型轨迹

外部来源的既有 `snapshot_ref` 现在填写 `snapshot:v1:<sha256>`，不公开本机绝对路径。
快照保留实际正文／结构化数据、URL、获取与观察时间、缓存、内容哈希、版本及截断；失败访问不伪造正文。
审计通过引用关联实际模型输入、工具调用 ID、参数、读取结果和模型输出。供应商思考字段仅用于内部协议回传，不导出推理内容。

引文必须属于所声称的同一来源；仓库／讨论判断还校验同仓库和同线程。仅允许空白展示差异时，保存回真实原文子串；字词、数字、标点改变仍拒收。
模型不能赋予自己人工审核身份、独立复现资格或 `scoring_eligible=true`。

## 5. 计分与前端映射

三项分数及总分仍由后端确定性规则计算。模型不直接给分，BE-07 首版不修改 0.2 映射、权重或类别阈值，讨论继续不自动计分。
前端选择 0.2 请求后，分别展示试验分、`coverage` 缺口、执行错误和 `external_review` 状态；不得把技术失败的低可验证性分写成研究造假或复现失败。

前端 FE-02／FE-03 按本合同接续；在真实接口联调完成前，Mock 原型不计作该版本前端验收通过。实现及运行方式见 backend `docs/credibility/durable-evidence.md`、`external-tools.md`。
