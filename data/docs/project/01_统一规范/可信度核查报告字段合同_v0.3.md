# 可信度核查报告字段合同 v0.3

版本：`credibility-0.3.0-draft`，2026-10-19，本地实现合同。沿用 [v0.2](可信度核查报告字段合同_v0.2.md) 的报告、执行质量和工具核查对象，新增引用核实率与未完全核实条目的结构化原因。该版本仍是草稿；本地实现及技术运行不代表已完成跨组验收或部署。

## 1. 请求版本及兼容

接口保持 `POST /v1/credibility/assessments` 和 `GET /v1/credibility/assessments/{id}`。省略请求 `schema_version` 时采用 `credibility-0.3.0-draft`；显式提供的版本决定 POST 排队快照及之后 GET 的公开序列化版本。GET 只读取持久化结果，不重新检索。

| 请求版本 | 公开报告结构 |
|---|---|
| `credibility-0.1.0-draft` | 原 v0.1 结构，不含 `coverage / execution / external_review / reference_verification_summary` |
| `credibility-0.2.0-draft` | 原 v0.2 结构，含 `coverage / execution / external_review`，不含 `reference_verification_summary` |
| `credibility-0.3.0-draft`（默认） | v0.2 结构加 `reference_verification_summary` |

数据库内部可以保存完整报告；旧版本公开投影在响应序列化时完成。旧记录缺少新增摘要时，可由其已保存的 `checks.references` 确定性推导，不触发网络访问。

```json
{
  "schema_version": "credibility-0.3.0-draft",
  "analysis_mode": "credibility",
  "source": {"type": "arxiv", "arxiv_id": "2106.09685v2", "upload_id": null},
  "model_id": "model_standard_v1",
  "rubric_version": "0.2-provisional-complete"
}
```

## 2. 新增报告字段

`report.reference_verification_summary` 是非空对象，由最终的 `checks.references` 推导。引用核查未运行、没有条目或不适用时仍返回对象，率为 null，不填 100%。

| 字段 | 类型 | 规则 |
|---|---|---|
| `verification_rate` | number?，0–1 | `matched_count / extracted_count`；分母为 0 时为 null，不四舍五入存储 |
| `denominator` | 固定 `extracted_references` | 分母是已提取条目，不能当作论文全部引用；是否完整提取另看 `extraction_complete` |
| `extracted_count` | integer ≥ 0 | 已提取引用数量 |
| `matched_count` | integer ≥ 0 | 最终 `matched` 数量，包含有来源证据解释的版本差异 |
| `unverified_count` | integer ≥ 0 | 最终 `unverified` 数量 |
| `not_checked_count` | integer ≥ 0 | 最终 `not_checked` 数量 |
| `metadata_conflict_count` | integer ≥ 0 | 最终 `metadata_conflict` 数量 |
| `extraction_complete` | boolean | 只有 `extraction_status=complete` 且无 `gaps` 时为 true；不因分数高而改变 |
| `unresolved_items` | ReferenceUnresolvedItem[] | 原始顺序下所有非 `matched` 条目，包含元数据冲突；已匹配项不重复列出 |

### ReferenceUnresolvedItem

| 字段 | 类型 | 含义 |
|---|---|---|
| `reference_id` | string | 对应 `checks.references.items[].reference_id` |
| `outcome` | `unverified / not_checked / metadata_conflict` | 保留该条目既有最终结果 |
| `reason_code` | enum | 下表中的确定性原因类别 |
| `reason` | string | 具体缺少的证据、冲突或失败原因；保留条目原说明 |
| `source_ids` | string[] | 对应该条目原有来源 ID，可查看原始抓取状态、时间与快照 |

原因通过条目 `reason` 的 `[reason_code] 具体说明` 前缀编码，摘要只识别本合同枚举；不使用模型再次判断。条目现有 `reason` 字段仍为字符串。旧条目没有可识别前缀时，冲突使用 `metadata_conflict`，未检查使用 `not_checked`，其余使用 `undetermined_reason`；不从不完整旧文案臆测失败类型。

| `reason_code` | 说明 |
|---|---|
| `target_not_found_in_scope` | 有界查询未获得足够匹配的目标，不能据此认定文献不存在或数据库未收录 |
| `year_mismatch` | 年份不一致且无足够版本证据解释 |
| `author_mismatch` | 署名无法确认一致 |
| `title_mismatch` | 候选题名不能确认是同一文献 |
| `identifier_mismatch` | 返回的文献标识与请求／引用标识不一致 |
| `invalid_arxiv_id` | 引用中的 arXiv 标识格式无效，无法据此查询 |
| `version_evidence_missing` | 题名／版本差异缺少可验证关系 |
| `source_fetch_failed` | 来源访问失败，须同时看 `source_ids` 的抓取状态 |
| `budget_exhausted` | 本篇补查时间／请求预算耗尽，保留已取得结果，不声称已完成剩余查询 |
| `insufficient_metadata` | 缺少足以识别文献的字段 |
| `personal_communication` | 私人通信无法通过公开文献来源验证 |
| `extraction_gap` | 提取范围或条目边界仍有缺口 |
| `metadata_conflict` | 已确认元数据冲突，或旧记录仅保留该结果类别 |
| `not_checked` | 旧记录未检查且没有更具体的机器编码原因 |
| `undetermined_reason` | 旧记录没有可识别编码；具体原因仍查看原文 |

## 3. 多来源与计分

引用核查可在 Crossref 未得到足够目标证据时，按后端声明的检索范围补查 arXiv、官方论文集和出版社来源。补查只有在文献身份及必要版本关系得到来源证据支持时才改判 `matched`；查询成功但没有适当目标不能当作核实成功。来源仍使用 v0.1/v0.2 的 `sources / candidates / evidence` 对象及闭合关联，不新增评分结果枚举。

本版本不修改 `0.2-provisional-complete` 评分映射、权重、类别或公式。相同固定 `checks` 在 v0.1、v0.2、v0.3 应得到完全相同的逐项分数、维度分数和总分。核实率为解释指标，不能再次乘入分数。新来源核实了更多条目后，条目结果发生变化，由既有规则自然重新计分。

补查保留每次来源的真实抓取状态。某来源失败后，如果该条目被其他来源充分核实，则该条目的技术缺口已恢复，引用执行步骤可以为 `completed`；保留的失败访问仍计入 `coverage.technical_failure_count`，不伪装所有请求成功。尚未核实条目关联的来源失败、未完成查询或预算耗尽使引用执行步骤保持 `partial`。该执行状态区分访问尝试与最终条目结果，不改变试验分。

## 4. 前端和数据组消费迁移

新调用请求 v0.3 或省略版本；现有前端显式请求 v0.1/v0.2 时继续收到原结构。前端本轮不改 UI，后续接入时展示试验分、`verification_rate` 百分比、`matched_count / extracted_count`、`extraction_complete` 和未核实列表。

- `verification_rate=null` 展示“暂无可计算引用核实率”。
- `extraction_complete=false` 时将比率说明为“已提取引用中的核实率”，不要宣称全文引用覆盖。
- 用 `reason_code` 做筛选或汇总，用 `reason` 和原来源证据解释具体条目。`unverified`、抓取失败和私人通信不等同于假引用。
- `metadata_conflict_count` 与 `unverified_count` 分开统计；`unresolved_items` 包含两者及未检查项。
- 旧版读取方升级版本之前无需解析新增字段。数据组与本地项目文档中的本合同保持相同内容。

验收包括三版真实 POST/GET JSON 形状、进程缓存清空后的持久化读取、默认版本、摘要的空分母／部分提取／冲突与失败原因，以及同固定检查的评分一致性；合同测试不得联网或调用模型。
