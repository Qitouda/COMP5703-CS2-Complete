### 自动多来源引用核查接入（2026-10-19，引用自动流程专项完成）

用户确认保持现有 `0.2-provisional-complete` 数值规则，将 arXiv、官方论文集和出版社补查接入后端自动流程，并要求结果携带核实率／未核实原因。现已在 Crossref 后对未确认条目按 arXiv ID／有界题名作者查询、同 ID 旧版本与提交历史、引用及元数据中的官方链接和有界论文集目录自动补查。候选需规范题名、全部已列作者及来源支持的日期／版本；不读取人工 37 条补查报告，不硬编码 LoRA／CoT 文献 URL，不将目录或 HTTP 200 当作核实成功。

公开新增字段先按[可信度报告合同 v0.3](../01_统一规范/可信度核查报告字段合同_v0.3.md)登记并同步实现。该引用专项当时默认 `credibility-0.3.0-draft`（现行默认已升级为 v0.5），`reference_verification_summary` 给出 matched／extracted 核实率、提取完整性和关联来源的结构化原因；显式 0.1／0.2 请求仍保留各自原返回形状。同固定 checks 的条目分、维度分和总分保持原规则，核实率不额外影响计分；前端页面本次未改。

官方传输已限制 HTTPS 主机／路径、公开 DNS、跳转、大小、时间、共享排队和成功缓存，所有访问及版本确认留不可变快照；失败尝试即使被其他来源恢复仍保留。预算耗尽、字段不足、私人通信、年份／署名／标识差异及范围内未找到目标分别给原因。新增开关 `REFERENCE_MULTISOURCE_ENABLED` 与补查预算 `REFERENCE_FALLBACK_DEADLINE_SECONDS`。操作和准确实现范围见 `backend/docs/credibility/reference-auto.md`。

`scripts/verify_reference_auto.py` 已实现引用专项验收：只读原 parsing lineage、校对原 PDF SHA 并重新解析，使用新空 provider state 真实查询，再以独立进程／新 artifactroot 禁 HTTP 复跑；输出原 0.2 引用分、率／原因、源代码／Rubric 摘要及真实 provider HTTP 审计。该脚本不运行 DeepSeek、主张或代码检查，不充当整篇模型验收。
