## 2. 共同判断规则

### 2.1 适用性

每个维度先判断 `applicable`、`not_applicable` 或 `undetermined`。

- `applicable`：该类检查与本文内容相关。
- `not_applicable`：有内容依据证明不适用，必须写理由与证据；不能因为材料缺失、没有查询到、超时而使用。
- `undetermined`：解析或材料不足，连是否适用都不能确定；分数为空，也阻止总体出分。

研究类型用于解释适用性，不按会议、发表状态、录用结果或声望决定可信度。

| 类型 | 主张 | 引用 | 代码／复现 |
|---|---|---|---|
| 实验／方法论文 | 核查核心实验主张 | 有参考文献时适用 | 核心结论依赖程序、实验时适用 |
| 理论论文 | 核查声明、定理条件和正文论证是否对应；不承诺自动证明数学正确 | 同上 | 纯理论且无计算实验依赖时可不适用；有核心实验时适用 |
| 数据集／基准论文 | 核查规模、构成、评测协议等核心主张 | 同上 | 核心结果依赖构建／评测程序时适用 |
| 综述／概念论文 | 存在可用本文内容核对的主张时适用；否则说明范围后可不适用 | 同上 | 没有可运行方法或实验结论时可不适用 |

没有识别出主张或引用时，先检查解析质量。只有确认原文确实不存在相应对象，才允许不适用；不得用空数组代替此判断。

### 2.2 证据与结论的强度

每条发现必须区分：`confirmed`（证据直接支持的事实）、`reported`（第三方陈述）、`unresolved`（待核实线索）。第三方复现报告即使内容详尽，仍为 `reported`，不能写成系统已亲自复现。

论文内引文需匹配到具体文本块，页码与文本块一致；关键数值还要核对单位和条件。外部证据需有来源、获取时间、与本文或仓库的关联依据，并保存可复查摘要或内部记录标识。链接存在不等于内容支持判断。

普通研究动机、写作风格、没有达到 SOTA、没有社区评论，不直接构成可信度风险。严重措辞必须有相应证据；模型置信度高不能替代证据。

### 2.3 何时允许出分

本稿采用保守门槛：适用性确定、约定范围完成、证据通过校验，且不存在未解决的计分相关问题时，才给分。

- 查询成功但无匹配为“未核实”，不是技术失败，但可能使该项无法评分。
- 超时、限流重试耗尽、解析缺失为检查失败或部分完成，不扣成论文低分。
- 一个适用维度无法评分时，该维度和总分均为空；其他已评分维度及已确认风险仍展示。
- 真正不适用的维度才可从总体分母中排除；全部不适用时返回无法评估。

该门槛可能提高“无法评估”的比例，尤其在引用未核实较多时。试验必须记录该比例，不为了生成总分而悄悄排除未核实条目。后续如允许部分覆盖出分，应另升规则版本并定义清楚门槛。

## 3. 主张与证据一致性 `claim_evidence`

### 3.1 选择与核查

从摘要与引言中选择影响读者理解主要贡献的、可用论文后文核查的主张；记录选择范围和排除理由。相同主张去重，复合句在必要时拆分。建议先以少量核心主张开展试验，但不把固定三条当完整覆盖：遗漏重要主张时必须说明并阻止该维度出分。

逐条记录主张原文及位置、重要性（`core`／`supporting`）、数据集／指标／基线／条件、检索过的正文与附录范围、支持或冲突证据。先比较是否是同一实验条件，再判断一致性。

### 3.2 条目规则

| `outcome` | 判准 | `score_rule_id` | 条目分数 |
|---|---|---|---:|
| `supported` | 关键条件与结果得到对应证据支持；不将有限支持扩大到全文认证 | `C_SUPPORTED` | 10 |
| `partially_supported` | 有直接证据，但主张范围大于证据范围或限定条件未充分表达 | `C_PARTIAL` | 7 |
| `not_found` | 必要部分可读取且检索范围充分，仍未找到该结果对应的支持；不是检索程序失效 | `C_NO_SUPPORT` | 4 |
| `contradicted` | 在相同条件下找到直接相反证据，影响局部结果 | `C_CONTRADICTION` | 2 |
| `contradicted` | 相同条件下的直接冲突推翻该核心主张的决定性结果；`importance=core`，需明确解释影响 | `C_CORE_CONTRADICTION` | 0 |
| `unable_to_determine` | 表格不可读、附录缺失、条件不清或证据有争议 | 无，`null` | `null` |
| `not_checked` | 尚未执行或该条执行失败 | 无，`null` | `null` |

`C_CORE_CONTRADICTION` 不凭“严重”形容词触发，必须保存主张、直接反证、条件一致性及对核心结论的影响。0 分也只描述此维度，不表示造假。

按 D-039，第一版维度分数取去重后全部纳入检查条目的最低有效分；摘要／引言关键主张的约定范围检查完成且全部条目有有效分才能汇总。任一条目 unable_to_determine／not_checked 或读取／遗漏缺口导致本维度无法评分，不能只取其余有效分而忽略缺口，也不把未知硬填为 0。已确认风险仍保留。此规则防止大量正常条目稀释一个关键问题；按 D-040 不对总体评级封顶，不按重复句子或重复 finding 累计扣分。

理论论文的 `supported` 仅表示所查声明与条件／论证对应，不表示证明已被自动验证，须写入限制。

## 4. 引用存在性 `reference_verification`

### 4.1 检查范围与匹配

对全部成功提取的文末条目建立稳定 ID，保留原始文本、论文位置和解析字段。提取失败的片段保留为缺口；不编造完整条目。相同引文在原文出现两次时保留两条位置记录，但外部查询可以复用缓存。

优先检查明确的 DOI／arXiv 标识；没有标识时使用标题、作者、年份等字段寻找候选。标识符不是无条件可信：返回记录需与原始引用的其他信息核对。预印本与正式版、作者缩写和年份差异需解释版本关系，不能机械判冲突。元数据存在性检查不证明被引论文内容真实，也不证明它支持正文论点。

### 4.2 条目规则

| `outcome` | 判准 | `score_rule_id` | 条目分数 |
|---|---|---|---:|
| `matched` | 唯一候选经标识及书目信息核对，与原条目一致或存在可解释的版本差异 | `R_MATCHED` | 10 |
| `metadata_conflict` | 文献身份已确定，但年份、作者等存在已确认且非版本差异的书目错误 | `R_MINOR_CONFLICT` | 7 |
| `metadata_conflict` | 有直接来源证实条目的标识与其标题／作者指向不同作品，排除解析错误后仍存在实质冲突 | `R_MAJOR_CONFLICT` | 3 |
| `unverified` | 无结果、多个候选无法消歧、来源互相矛盾或书目信息不足 | 无，`null` | `null` |
| `not_checked` | 尚未查、超时或无法有效执行 | 无，`null` | `null` |

检索无结果不得映射到 `R_MAJOR_CONFLICT`，也不得输出“虚构引用”。疑似标识损坏但作品可正确确定时，记录为书目问题，解释原因，不使用更严重的错配规则。

按已确认的 D-036，无可靠匹配须在总评附近醒目提示“引用存在性待核实，建议复核”，并可展开原始条目、查询来源、候选与原因；对应 `verification_gap` 的 certainty 为 unresolved，并生成 `assessment_gap`。只有直接冲突证据且排除解析／版本差异后，才按信息错误规则计分；单凭未核实不强制扣分，条目与引用维度仍为空分。

维度分数取所有条目的最低有效分；任一 `unverified` 或 `not_checked` 导致本维度无法评分。全部成功提取条目仍须尝试检查，不能找到一个问题就提前结束。

### 4.3 提取完整性与查询覆盖率

报告分别记录原文总数（无法确定时为空）、提取数、执行过有效查询的数量、匹配数、冲突数、未核实数和未检查数。

- 查询完成率 = 已检查数 / 已提取数；分母为 0 时为空。
- 提取覆盖率 = 已提取数 / 已确认的原文总数；总数未知或为 0 时为空。
- 只有提取边界、条目分割和缺口检查均通过，才标记提取状态 `complete`；单纯成功返回一些文本不够。
- 原文总数未知时，即使提取状态为 `complete`，提取覆盖率仍为空，只能表述为“识别到的参考文献范围内未发现解析缺口”。此时允许按全部已提取条目评分，但必须保留范围限定；评分不认证原文无遗漏。
- 提取状态为 `partial` 或 `failed` 时，本维度不出分。真实原文没有引用且检查确认时可不适用。

人工验证样本应统计真实条目数，以检验自动的 `complete` 判定是否可信；提取漏项必须单独计入评测，不能藏在查询完成率中。

## 5. 代码与外部复现线索 `code_reproduction`

### 5.1 先确定代码来源和搜索范围

依次检查实际可取得的论文正文、附录、随附材料、明确关联的官方项目页和仓库。记录各来源的搜索／获取结果；外部资源获取失败不得写成不存在。

确认仓库归属要有论文指向、项目页声明或仓库中明确对应的论文标识。仅同名、仅出现 GitHub URL、仅存在空仓库均不足以确认“可访问的实现”。记录相关版本；无法确认实现对应哪一版论文时说明限制。

代码可访问意味着存在可读取、与论文方法相关的实现内容；不意味着能够运行、完整复现或数值正确。声称“不开源”或隐私限制作为作者陈述保存，不推断动机。

### 5.2 反馈筛选

检查与论文结果相关的公开 issue／评论，保留原始讨论、关键回复、关闭原因和修复情况。分页或服务限制使约定范围未读完时，记为部分完成。不能用关闭状态单独证明问题已经修复。

- 独立成功反馈需明确对应论文／实现，说明任务、条件和结果，不只是点赞或“works”。发布者与作者的独立关系有依据，无法确认独立性时不加独立复现分。
- 负面反馈需对应核心结果和相关版本。只有一般安装失败、环境不明、无上下文的抱怨时，保留作上下文，不直接扣为结果复现失败。
- 具体、相关但尚有关键争议的反馈记为 `unresolved`；该维度暂不出分，保留问题与作者解释。
- 明确归属无关论文、旧版已修复且有修复依据、普通使用问题，可以排除计分，记录理由。缺少关联信息本身不能直接判无关。

### 5.3 计分阶梯

在适用性与搜索范围完整、没有计分相关未核实问题的前提下：

| 条件 | `score_rule_id` | 分数 |
|---|---|---:|
| 在已检查来源中未找到可访问代码；不存在被误写为无代码的获取故障 | `K_NOT_FOUND` | 4 |
| 找到明确关联、可访问的实现，未发现合格的独立成功反馈，也没有符合下面降分条件的负面反馈 | `K_AVAILABLE` | 7 |
| 具备可访问实现，且有符合要求的独立成功反馈 | `K_INDEPENDENT_SUCCESS` | 9 |
| 存在与当前所评版本／核心结果相关的具体复现问题，作者明确确认该问题，或至少两份有独立性依据、条件可比较的报告相互印证，且没有有依据的解决记录 | `K_CORROBORATED_FAILURE` | `min(基础分, 3)` |

基础分按前三行取值；负面条件成立时再应用最后一行。相同讨论被转贴不算两份独立报告。若成功与失败报告条件不可比较且无法消歧，使用无法判断，不挑选有利的一方。

`K_CORROBORATED_FAILURE` 依然表示有充分来源的第三方线索，不表示系统亲自验证失败。代码项不会得到 10 分。无公开代码的 4 分表示可核查材料不足，不是作者欺骗的判断；无社区反馈但代码可用仍是 7 分，不按复现失败处理。

实现对应关系不明、相关资源无法访问、必要讨论未读完或关键反馈未解决时，本维度为 `null`。理论等真正不需要代码的情况使用不适用，不给 0 分或 10 分。

## 6. 分项汇总、总体类别和提醒

### 6.1 总分

三个维度的原始权重均为 1。只排除经过确认的 `not_applicable` 维度，其余维度必须全部有分：

```text
若任一维度 applicability=undetermined，或任一 applicable 维度 score=null：
    overall.status = unable_to_assess
    overall.score = null
    overall.category = null
否则若适用维度数为 0：同上
否则：
    score = round_half_up(sum(适用维度分数) / 适用维度数, 1)
    按该展示分数映射类别
```

使用十进制四舍五入（half up），阈值判断使用已经保留 1 位小数的同一个分数，避免页面显示 8.0 却给出 8.0 以下类别。模型不得重写确定性计算结果。

D-040 已确认保留平均汇总及由得分映射的类别；单个重大／关键问题不自动改低总体类别，须通过低分与 material_finding 提醒清楚表达。草案的等权数值和具体类别阈值仍待校准，不能把这项产品选择写成整套数值规则已获批准。

### 6.2 类别

| 展示分数 | `category` | 用户文案 |
|---|---|---|
| 8.0–10.0 | `no_significant_concerns` | No significant concerns found |
| 6.0–7.9 | `some_concerns` | Some concerns |
| 3.0–5.9 | `significant_concerns` | Significant concerns |
| 0.0–2.9 | `critical_concerns` | Critical concerns |
| `null` | `null`，不进入四档 | Unable to assess |

类别是当前建议量表的聚合结果，不表示整篇论文已被认证，也不表示主观欺诈。报告必须显示检查范围和局限。总体摘要不得因为类别较高而否认已经存在的具体风险。

### 6.3 提醒与缺口

- 每个已评分且小于 6 分的维度产生一条 `low_dimension_score` 提醒，放在总体结果旁，链接到该维度和相关 finding。
- 无法评分的适用项或适用性未确定项产生 `assessment_gap` 提醒；不伪装成低分。
- 重大／关键风险 finding 另产生 `material_finding` 提醒，即使总分较高或总体无法评分也不得隐藏。
- 提醒不改变总分或类别，遵守不设置单项总评上限的既有决定。

## 7. 边界与计算案例

以下均为**合成规则案例**，用于检查实现，不是对真实论文的评价，不作为人工 Gold 或准确率证据。

| ID | 情景／分项（主张、引用、代码） | 预期 |

## 8. 人工校准与效果记录

沿用已有[样本与复评记录](第二轮_可信度核查样本与复评记录.md)，不另建一份样本主表。人工先记录事实与证据，再套用规则；将判准分歧与计算错误分开。

建议记录以下指标，当前不预设达标阈值：

| 指标 | 计算口径 |
|---|---|
| 风险召回 | 人工确认且在声明范围内的重要风险中，被系统正确识别的数量／该类风险总数；条目去重并说明匹配规则 |
| 正常条目误报 | 人工确认正常的可比较条目中，被系统错误报为风险的数量／正常条目总数 |
| 证据错误 | 原文不存在、位置不符、外部来源误关联、证据不支持结论分别计数；标明总检查条数 |
| 提取覆盖与查询完成率 | 依第 4.3 节分开记录；人工原文总数未知时不填提取覆盖率 |
| 未核实比例 | 引用 `unverified` 数／已提取引用数；分母为 0 时为空；未检查数另列 |
| 无法评估比例 | 总体无法评估的终态报告数／纳入统计的终态报告数；先行解析失败单列，不能从统计中悄悄删除 |
| 重复运行稳定性 | 固定论文、外部证据快照和规则版本，比较条目判断、证据及最终类别变化 |

开发与最终复评使用的样本应可区分；不能只使用调过提示词的案例证明泛化效果。合成案例只验证计算和状态；真实问题识别仍需公开论文与人工证据。
