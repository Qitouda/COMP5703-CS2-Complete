## 验收前准备

固定前后端、解析器、模型、Prompt、新可信度 Rubric／schema 和旧评分版本。数据组提供有明确问题、无明显问题、争议／未核实的 ML 论文样本，至少包含 Manifest 内外 arXiv、可解析 PDF，以及不同论文类型；每个预期有人工证据或公开来源，不能以模型输出本身为 Gold。外部页面的核查时间必须保留。

首批规模已按 D-042 选择 A（3–5 篇）：当前 4 篇候选为 P002（旧分 7.2）、P004（8.6）、P030（5.4）、P005（7.6），版本、候选证据与条件集中在[样本与复评记录](../数据样本与%20Rubric/第二轮_可信度核查样本与复评记录.md)。旧分仅辅助正反面选样。P030 原 PDF 当前获取受阻，存量解析里的质量／速度问题仍待原表复核；其余已定位证据也不代表范围完整或正式 Gold。先覆盖 C02 支持／支持有限和 C06 无法判断／N/A／受控故障，C03／C04 外部核查及真实接口验收随后补齐。故障注入不算论文反例，未执行项不登记通过。

## C01 双模式与通用 ML 输入

步骤：分别用 ML arXiv 链接和 PDF 选择旧评分与新可信度核查；查看进度及最终页面。另以非 ML 或无法解析输入检查失败说明。

预期：两模式互不混算；新模式无 ICLR 准入或 venue 必选条件；返回内容对应实际论文。无法评估时说明原因，不回退 Mock。旧评分能按原合同运行。

报告展示对照（D-035）：轮询 queued／processing 快照时 report=null，页面显示阶段和进度；分项提前完成也不展示临时结论或分数。任务终态后展示完整或部分报告，明确剩余缺口；completed 不等于三维全部核实。

证据：输入、运行 ID、论文／模型／解析版本、页面与 API 结果。

## C02 主张与论文内证据

步骤：用数据组已标注的“核心主张有支持”“主张仅部分支持／缺结果”“后文明确冲突”样本检查逐条 finding。

预期：报告能定位主张和对应的后文位置，区分缺证、矛盾与无法判断；普通愿景句不伪装为已验证实验主张；人工确认的重要问题是否漏报、正常对照是否误报均有记录。

摘要／引言范围对照（D-041）：固定同一 PDF 中影响主要贡献的关键可验证主张预期清单，核对提取、去重、排除依据与遗漏；对应证据可以位于方法、结果、图表或附录。scope_complete 表示约定主张范围完成，不表示全文每条主张已核查。固定条数截断、遗漏范围内重要主张或必要证据不可读时，不得声明范围完整或强行出分。首例单条 supported 不替代其余关键主张检查。

证据：人工标注、原文页码／章节、模型 finding、差异记录。

## C03 全部文末引用的存在性

步骤：选带 DOI、无 DOI、信息错误或无法匹配条目的论文，核对文末条目提取数与逐条核查结果。

预期：全部**成功提取**的文末条目进入检查；展示已提取／已检查／未核实数量及元数据来源。可匹配、明显冲突、未能核实可区分；数据库检索不到不直接写“虚构引用”。文末解析失败时展示覆盖缺口。

提醒对照（D-036）：有效查询无可靠匹配时，总评附近醒目提示“引用存在性待核实，建议复核”；展开后可见原始条目、查过的来源、候选和无法确认原因。API 为 unverified、unresolved 的 verification_gap 和 assessment_gap，条目与引用维度分数为空；不能仅凭无匹配扣分或确认错误。另以“DOI 对应另一篇作品”的固定来源样本对照：排除解析与版本差异后才按 metadata_conflict 记录并依审核 Rubric 计分。

证据：原始参考文献页、提取条目、外部元数据响应摘要与时间、报告状态。

## C04 代码公开及复现讨论

步骤：检查正文无链接但补充材料有代码、官方仓库公开且无相关 issue、有明确正面反馈、有负面反馈并附作者回复／修复，以及无代码适用性样本。

预期：报告列出查过的位置；未找到时只说“在已核查来源中未找到”。仓库与论文的关联有依据；第三方评论保留原始链接、时间和上下文，不写成系统亲自复现。无反馈不等于成功或失败；代码维度不授予代表亲自复现的满分。

证据：论文／补充材料位置、仓库与 issue URL、抓取时间、报告截图。

## C05 评分、类别与低分提醒

步骤：用确认后的 Rubric 样本核对三维分数、总分、英文类别；加入“一项明显低分、其他项高分”的案例。

预期：新分数不引用旧五维分数；按适用维度汇总，不设单项总评上限；低分项在总评附近醒目可见且能展开依据。类别只能描述风险，不作欺诈裁决。精确阈值必须取已审核 Rubric，不能从本稿推测。

汇总对照（D-039～D-040）：同维度多条有支持、一条有直接冲突时，主张维度取最低有效分，不被其他正常条目平均稀释；同一主张重复出现不能重复扣分。有无法评分条目或范围缺口时，该维度及总分留空，已确认问题仍显示。三维均有有效分时，总体平均汇总并按规则映射类别，低分或重大／关键 finding 不另改低类别，也不能被总体分数隐藏。

证据：Rubric 版本、人工预期、实际计算记录、页面与 API 响应。

## C06 不确定、不适用与技术失败

步骤：制造元数据无匹配、GitHub 无相关评论、理论论文无代码需求、外部 API 失败及 PDF 解析失败场景。

预期：“未能核实”“未发现反馈”“不适用”“Unable to assess”分别表达；技术失败说明原因，不输出伪低风险结论；可恢复故障有重试路径。外部查询故障不能被当成论文风险。

按 2026-10-01 确认的总体出分口径，任一适用维度无法评分时，总分和类别均为空；仍展示已确认发现和其他分项结果，有证据的重大风险仍需提醒。纯理论论文的代码项只有具备不适用依据才排除；所有维度均不适用时也无法生成总分。第一周仅完成主张链路时，其他未运行项如实显示“尚未检查”，总分留空。

重试对照（D-037）：外部服务超时或限流后，终态页面保留已确认发现与其他分项，受影响分项及总分／类别为空，显示故障来源和“新建任务重试”按钮。点击后复用原输入与用户选择，新建整个核查任务并取得不同运行 ID；原结果仍可追溯，不覆盖为新结果。若模型或版本已不可用，明确提示重新选择。成功重试的结果仍须依据实际来源，不得自动回退合成数据。

优先主张链路另测一组对照：必要章节和附录可读、检索充分但未找到支持，按主张缺证记录；必要表格读不清或附录缺失，则按无法判断或技术缺口记录。两者不能都标成冲突，也不能都视为已完成风险判断。

证据：输入、故障方式、状态码或运行记录、页面信息。

## C07 人工复评与旧功能回归

步骤：数据组按固定样本检查重要风险遗漏、正常论文误报、引用覆盖率和证据真实性；前后端复查旧五维报告、证据和输入路径。

预期：模型分析交付与效果达标分别记录；缺陷有责任人和下一步。旧功能未被新 schema 或页面改造破坏。

证据：[复评记录](../数据样本与%20Rubric/第二轮_可信度核查样本与复评记录.md)、测试／联调记录与截图。
