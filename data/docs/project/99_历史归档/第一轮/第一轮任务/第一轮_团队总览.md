## 3. 启动顺序

```text
数据处理组建立公开论文样本集并完善五维评估 rubric
→ 后端组使用样本和 rubric 实现论文处理、大模型调用与结构化输出
→ 前端组依据字段合同开发页面，并使用示例或真实结果联调
→ 数据处理组评测模型结果并向后端反馈调优方向
→ 产品组按已锁定的 MVP 范围组织最终验收
```

数据处理组不需要等待其他组先提供数据。后端组负责“如何调用模型并稳定地产生结果”，数据处理组负责“如何判断结果是否合理”。

## 4. 原型运行流程

```text
用户输入 arXiv 链接或 PDF
→ 前端把输入交给后端
→ 后端调用论文解析与大模型评估流程
→ 后端校验并返回结构化结果
→ 前端展示完整报告和证据
```

报告至少包含五维评估、主要优点、主要问题、未解决问题、总体判断、置信度和论文内证据。失败时必须说明原因，不能生成不存在的内容。

## 5. 跨组协作原则

1. 每项任务必须确定一名唯一负责人和目标日期。
2. 前端、后端和数据处理组共同使用统一字段合同。
3. 五维名称、字段结构和产品边界保持不变；评分指标、评分锚点、证据规则和测试方法由数据处理组完善。
4. 大模型调用、Prompt 编排、结构化输出、推理调优和运行稳定性由后端组负责；数据处理组提供样本、rubric 和效果反馈。
5. 三周 MVP 的调优是模型选择、Prompt、参数、上下文和 few-shot 优化，不要求训练或 Fine-tuning 大模型。
6. 影响范围、进度或验收的事项提交总负责人决定；其他技术实现由对应小组决定。
7. 三周内不临时扩大 MVP；新增需求进入 Backlog。
