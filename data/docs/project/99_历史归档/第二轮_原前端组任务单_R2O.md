# 第二轮原前端组任务单 R2O（归档）

总负责人：曾博成。具体实现：傅饶、吴冬乔，组内分配及日期待确认。

本轮继续完善现有产品前端，重点参考 CSPaper 的论文工作区、信息层级和状态表达。新增功能要先形成使用流程及接口方案，交后端确认后再开发。

## 本组任务

| 编号 | 任务 | 交付物 | 验收条件 |
|---|---|---|---|
| R2O-FE-01 | 整理现有体验问题和改进清单 | 页面问题、对应参考图、优先级及预期行为 | 每个改动能明确到页面或状态，而非笼统要求“更好看” |
| R2O-FE-02 | 完成确认后的体验优化 | 页面、交互、状态和改动截图 | 符合参考规范，报告关键内容可读，已有操作仍可完成 |
| R2O-FE-03 | 提出本地结果等新增需求方案 | 用户流程、字段、数据来源、接口需求与异常处理 | 后端能够判断可行性和工作量，产品组可决定是否纳入 |
| R2O-FE-04 | 完成联调与页面验收材料 | 真实操作记录、截图、版本及已知问题 | 实现功能按已审核路径可复现，视觉和功能检查均有证据 |

本地结果展示的方案设计属于本轮准备工作，功能开发是否纳入待确认。不能将静态演示列表作为已读取真实历史结果的交付。

## 重点页面

- 输入页：arXiv 与 PDF 入口、输入校验和提交反馈清楚。
- 处理状态：排队、处理中、完成、失败及重试或返回路径明确。
- 报告页：标题、作者、五维评分、理由、优缺点、总体判断和置信度层级清晰。
- 证据与详情：用户能够找到证据原文以及页码或章节，查看后能返回上下文。
- 窄窗口及内容较长时：关键按钮不被遮挡，长标题和正文能正常换行。

## CSPaper 参考方式

按 [CSPaper前端参考与验收规范](第二轮旧方案_R2O/CSPaper前端参考与验收规范.md) 提交改动对照。主要参考宽松留白、醒目标题、粉紫渐变工作区、大圆角白色内容面板、图标导航与清晰的状态边框。截图里的 Code Check、Reference Check 等模块不自动成为本项目需求。

## 交接与验收

纯展示与交互优化可独立推进。涉及新数据或接口的任务，先按 [接口与需求协作说明](../01_统一规范/接口与需求协作说明.md) 给后端方案，确认之后联调。

前端提交页面改动及操作路径，产品组汇总到整体验收文件。整体验收路径必须经过曾博成审核，最终按该路径验收，不能仅以参考截图相似作为完成标准。
