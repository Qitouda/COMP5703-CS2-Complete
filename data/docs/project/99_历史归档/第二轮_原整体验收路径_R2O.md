# 第二轮原整体验收路径 R2O（归档）

状态：v0.1 待审核。产品组编写，各组补充验证细节，整条路径需经曾博成审核后作为正式验收依据。当前没有任何路径被登记为已通过。

本轮验收同时检查原有流程、确认后的改进、数据评估交付和前端体验。数据组的分析交付与模型效果分开记录；历史结果展示只在范围确认后纳入。

## 验收前准备

记录前端、后端及数据版本，实际模型、Prompt、Rubric、解析器版本，以及启动方式。准备已确认的 ML arXiv、上传 PDF、非 ML 或无法评估样本，以及本轮差异与修复样本。样本名单和数量由各组确认，保持输入版本可回查。

确认本轮任务清单、候选需求纳入决定和本路径审核版本。各组自查可以先开展，最终验收必须依据审核过的路径。

## A01 arXiv 输入至完整报告

前置：真实后端可用，准备一篇已确认可评估的 ML arXiv 论文。

步骤：前端提交链接或 ID，查看任务状态，等待完成，打开五维报告并查看一条关键结论的证据。

预期：输入论文、报告和证据对应；状态清楚；报告关键内容齐全。结合通用输入范围，使用 Manifest 内外样本核对，不得返回固定论文内容。

证据：输入版本、任务或结果编号、实际版本、页面截图及必要运行记录。前后端共同执行。

## A02 PDF 输入至完整报告

前置：有效、可解析且已确认适用的 ML PDF。

步骤：选择 PDF、上传并提交，等待完成，再查看报告和证据。

预期：上传文件可进入实际处理流程，展示该文件对应的报告；私有输入不被默认公开。arXiv 流程通过不能替代本项。

证据：输入文件标识、运行编号、状态及报告截图。前后端共同执行。

## A03 无法评估与失败恢复

前置：准备非 ML 输入，以及与本轮改动相关的无效输入或失败场景。

步骤：提交非 ML 输入，检查无法评估结果；分别检查无效输入和适用的读取或服务失败场景，按页面提示返回、重试或修改输入。

预期：非 ML 等不可评估输入不生成分数，错误原因清楚；失败时不回退为 Mock 报告。仅可重试场景提供重试，不可重试场景引导修改输入。处理阶段和失败内容符合合同。

证据：各场景输入、错误结果、页面反馈及恢复步骤。前后端共同执行。

## A04 模型与人工评估差异

前置：数据组已准备同论文版本、同评估规则下的人工判断和真实模型报告。

步骤：按样本逐项核对评分、理由、证据、遗漏及不确定性，检查人工分歧和更正建议。

预期：差异有原文或规则依据，原因假设标注清楚，建议能转为后端任务。样本数量、衡量方式和目标以确认后的评测方案为准。

证据：评估差异表、人工记录、真实报告、证据位置。数据组执行，产品组检查交付完整性。模型尚未改善不直接判定本项分析交付失败。

## A05 后端改进及效果复评

前置：确认后的数据建议已经实现，并有调整前后版本。

步骤：逐条对照建议与实现，用相同输入验证预期行为，再由数据组复评。必要时检查其他样本是否引入新问题。

预期：后端实现与确认建议一致且相关功能通过验证；效果如实记为改善、无明显改善、变差或证据不足。没有证据的效果提升不登记为成功。

证据：建议编号、实现版本、前后结果及复评结论。后端负责实现验证，数据组负责效果判断。

## A06 前端体验与 CSPaper 对照

前置：已确认的页面改进清单及对应原始参考图。

步骤：检查输入、状态、报告及证据页面；对照标题层级、工作区、导航和状态表达；在常用桌面与窄窗口下操作关键流程，并检查长标题和缺失数据。

预期：符合前端参考规范，关键报告内容可读，操作入口明确，没有遮挡或关键内容溢出；空值不显示为零分。只检查本项目确认的功能，不要求复制参考产品的额外模块。

证据：页面前后截图、窗口尺寸、操作记录和版本。前端执行，曾博成审核。

## A07 本地运行结果展示 条件路径

仅在候选功能被确认纳入本轮时适用，否则登记“未纳入本轮”，不能计作验收通过。

步骤：产生新结果，打开历史列表，进入对应报告并返回，检查同论文多次运行、空列表及读取失败。若纳入跨重启保存，重启后端后再次打开同一报告。

预期：列表与详情来自真实保存结果，打开历史记录不触发新分析，论文及运行信息一致。若仅确认当前会话记录，则按该范围修订入口与预期，不声称具备持久历史功能。

证据：纳入决定、实际接口与保存方案、运行标识、前后页面及适用的重启验证。前后端共同执行。

## A08 本轮交付与遗留项

步骤：按任务表检查各组交付物、启动与复现说明、前端改进、数据差异及复评记录，并核对延期和剩余问题。

预期：纳入本轮的工作都有结果或明确处理决定；剩余模型问题有原因、后续方向和责任人；任务状态与证据一致。曾博成记录本轮验收结论。
