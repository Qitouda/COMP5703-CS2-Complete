# 范围变更记录：新增落地页

按《MVP 产品基线 v0.2》§15 的格式登记。本文件放在前端仓库，是因为
`00_资料/规范/` 不在任何 git 仓库里；合并后请产品组同步回基线文档。

```text
变更内容：
  在现有四个页面（输入 / 进度 / 报告 / 错误）之前增加一个落地页，说明产品是什么、
  五个维度评什么、流程怎么走、以及明确不做什么。页面内有两个入口按钮进入工作区。

用户价值：
  基线 §10 的用户流程假设用户已经知道这个工具是什么。在 client meeting 和课程演示
  里不成立——第一次看到的人直接落在一个输入框上，无法判断这个分数代表什么、
  可信到什么程度。落地页把 §2.2 的产品定位、§6 的五维 rubric 和 §9 的范围边界
  放在使用之前，降低"把 7.6 分当成录用预测"的误读风险（§13 已列为风险项）。

提出人：吴冬乔（前端）

影响模块：
  仅前端。新增 src/components/LandingPage.tsx 与对应样式；App.tsx 增加一个
  hasEntered 状态用于路由。不新增接口调用，不改字段合同，不动后端与数据组。
  落地页上的示例分数是写死的静态插图，不读取任何接口。

时间与成本影响：
  约半天前端工作量。无接口、无后端、无模型成本。

替换或延后的现有工作：
  无。FE-01~FE-04 已全部完成（见 CHANGELOG v1.0），本次为在其之上新增，
  不占用未完成任务的时间。

决定人：吴冬乔
决定日期：2026-09-13
```

## 与基线的冲突点

§9「明确不属于 MVP」排除了"账号、付费和复杂权限系统"。本次新增的落地页
**不包含**上述任何一项：没有账号、没有登录、没有付费、没有权限。它只是一个静态
说明页。如果产品组认为仍然越界，删除 `LandingPage.tsx` 并把 `App.tsx` 里的
`hasEntered` 初值改为 `true` 即可恢复原流程，不影响其他代码。
